# Glass UI/UX Refresh Plan

## Goal

Restyle the OpenLens frontend from the current flat stacked layout into a
modern glass-style experience with a better search flow: a hero search
moment, a sticky frosted header, a filter sidebar, and refined result cards —
without touching the backend or regressing accessibility.

## Success Criteria

- Empty state shows a hero search panel; after searching, a sticky frosted
  header keeps query + mode visible while results scroll beneath it.
- Controls are no longer one long stack: filters live in a collapsible
  sidebar, results in the center column, diagnostics stays a lazy rail.
- Glass treatment (translucency + blur + hairline border) is selective —
  header, hero, sidebar, rail — while result bodies stay solid for
  readability; full keyboard + screen-reader flow keeps working with zero
  axe critical violations.
- Every existing surface still renders every backend field it renders today
  (signals, story groups, commerce attributes, AI digest + sources,
  provider prefs, request id); no speculative UI for unshipped fields.
- Cache lookup outcome (hit/miss/error) surfaces as a rail badge — the
  one shipped diagnostics field with no UI today.
- All frontend gates green: `lint`, `format:check`, `test`, `build`,
  `npm audit --omit=dev`; backend tree untouched.

## Approach

Workspace facts shaping this plan (verified 2026-10-28 against the tree):

- `frontend/src/App.tsx` (~275 lines) stacks everything vertically:
  `SearchForm`, `ModeSelector`, `FilterToggle`, `FilterPanel`,
  `ProviderPrefsControl`, then results, pagination, lazy diagnostics rail.
  The flow fix is layout + disclosure, not new components for new data.
- `frontend/src/index.css` (~431 lines) owns the `--ol-*` token system
  (light enterprise theme, AA-cleared accent pairs) and every surface
  class (`.ol-header`, `.ol-card`, `.ol-drawer`, `.ol-chip`,
  `.ol-skeleton`, …). Task 18 finished this system with axe
  zero-critical, keyboard/Escape handling, `aria-live` announcements, and
  a lazy-loaded diagnostics rail under a bundle budget — all preserved.
- `ResultCard.tsx` renders title link, provider/`also_from` badges,
  snippet, attributes, understanding line, score + three disclosure
  toggles (breakdown, reasons, warnings), and the AI block with sources.
  Restyle keeps its data logic and `data-testid` hooks; only classes and
  grouping change.
- `components/ui/` holds 9 hand-rolled primitives (`Button`, `Card`,
  `Chip`, `Badge`, `Drawer`, `Select`, `Skeleton`, `TextInput`, `Toast`)
  with render tests. Glass arrives as additive token + class variants,
  never rewrites of primitive APIs.
- Binding constraints from `docs/workflow/v1/frontend_context.md`: no
  edits under `src/` (backend), mirror `api/schemas.py` only, fetch lives
  in `api/client.ts`, no hardcoded hosts or secrets in `frontend/`.

Key decisions:

| Decision | Recommendation | Why |
|---|---|---|
| Theme base | Keep the light `--ol-*` enterprise theme; add frosted-glass tokens | Task 18 contrast work and axe gates assume it; a dark-mode overhaul would re-open every AA pair |
| Where glass goes | Sticky header, hero panel, filter sidebar, diagnostics rail only | User asked for glass; house anti-slop guidance forbids blur-on-every-surface, and long snippets stay readable on solid cards |
| Palette | Teal accent stays; no purple/indigo gradients, no gradient headline text | Keeps brand continuity and avoids the top AI-tell looks |
| Typography | Keep the system stack; add weight/size hierarchy where flat | Avoids the Inter-everywhere tell; hierarchy fixes blandness more than a new font |
| Motion | Short fades/transitions on disclosure + rail only, all gated behind `prefers-reduced-motion` | Polish without scroll-jacking; reduced-motion users get instant state changes |
| Flow shape | Hero (empty) → compact sticky header + sidebar workspace (results) | One layout shift at first search; filters stop competing with results for vertical space |
| Component churn | Keep `data-testid` hooks and primitive props stable; move DOM, not APIs | Minimizes test rewrites; existing `App.test.tsx`, `ResultCard.test.tsx`, a11y tests stay meaningful |

Rejected: dark glass theme (re-opens all contrast pairs), glass on every
card (readability + slop), bento/3-card marketing grid (this is a tool, not
a landing page), per-keystroke search (explicit submit stays, per T12
debounce note).

## User Flow + Feature Map

Current flow (verified in `App.tsx`): land on stacked controls, submit,
read stacked results with chips, pagination, and drawer. Every control
competes for one column, so filters push results down and the query
scrolls away.

New flow (one layout shift at first search):

| Stage | User does | UI surface |
|---|---|---|
| Land | Type query, pick mode | Hero panel |
| Search | Submit, skim count | Sticky header, skeletons |
| Refine | Set filters, prefs | Sidebar, chips |
| Inspect | Open scores, AI | Card disclosures |
| Diagnose | Check timing, errors | Frosted rail |
| Page | Next, previous | Pagination |

Feature placement (every item already exists on the wire in
`api/schemas.py` mirrored by `api/types.ts`; nothing speculative):

Hero + sticky header:

- Query input with non-blank/≤1000 validation (`SearchForm`, logic
  unchanged, restyled into the hero then the compact header).
- Mode selector for the 5 modes (`ModeSelector`).
- Mode-suggestion chip from `diagnostics.query.suggested_mode`;
  explicit mode always wins (existing rule kept).

Sidebar (collapsible; collapses to a button on mobile):

- Sponsored toggle (`exclude_sponsored`), price/location/facilities
  commerce constraints, `prefer_*` preference keywords, block/allow
  domains, exclude term (`FilterPanel` + `FilterToggle`, same wire
  keys via `buildFilters`).
- Provider include/exclude/primary (`ProviderPrefsControl`, only
  known providers offered).
- Active-filter chips with per-filter clear + backend
  `applied_filters` attribution (`Chip` row + `AppliedFilters`).

Results column:

- "Showing N of M" count + story-group headers from
  `metadata.story_id` (`ResultList.groupByStory`, first-seen order).
- Loading skeletons, empty, and error-envelope states (`States`).
- Server-side pagination bound to `limit`/`offset`/`total`.

Result card (bodies stay solid; hierarchy + disclosures refined):

- Title link, snippet, provider + `also_from` federation badges.
- Commerce attribute line (price, location, facilities, published).
- AI understanding line (`ai_intent`, `ai_entities`, model label).
- Score breakdown: provider vs final score + `signals` bars in
  `SIGNAL_ORDER` (`resultSignals` reader).
- AI digest block with `ai_model` label, perspectives, and `Sources`
  links from `ai_citations`; renders only when `ai_summary` exists.
- Reasons/warnings disclosures; trust warnings visually distinct.

Diagnostics rail (lazy chunk, frosted):

- Live/degraded badge (`fallback_used`), copyable `request_id`.
- Provider latency/result-count/cost timeline; plugin-execution
  timeline with stage/status/latency (`summarizePluginExecution`).
- Query provenance: intent, effective vs suggested mode, added terms.
- Cache badge from `diagnostics.cache.status` (hit/miss/error) — the
  one shipped diagnostics field with no UI today; wave 2A adds it.
- Error list + `Developer details` raw disclosure (unchanged).

## Steps

Execution uses `docs/workflow/v1/workflow.js` with a new
`glass-ui_spec.json` (authored on `go`: copy `enterprise-ui_spec.json`,
point `plan_path` here, waves below). File ownership is disjoint per agent;
`src/` (backend) is read-only for all.

1. **Wave 0 (solo): tokens + glass primitive + shell grid.** Extends
   `index.css` with frosted tokens (`--ol-glass-*`: translucent washes,
   `backdrop-filter` blur values, hairline borders, layered shadows) and
   responsive shell grid classes (sidebar / results / rail, 360/768/1280
   breakpoints); adds one `GlassPanel` ui primitive (variant of `Card`,
   additive props only). Owns: `frontend/src/index.css`,
   `frontend/src/components/ui/GlassPanel.tsx`,
   `frontend/src/components/ui/index.ts`.
2. **Wave 1A: hero + sticky header search.** Empty-state hero panel
   (large glass `SearchForm` + `ModeSelector`); post-search compact
   sticky frosted header reusing the same form components. Owns:
   `frontend/src/App.tsx` (shell regions only),
   `frontend/src/components/SearchForm.tsx`,
   `frontend/src/components/ModeSelector.tsx`.
3. **Wave 1B: results restyle.** Refined `ResultCard` hierarchy (title row,
   badges, snippet, attribute line, disclosure groups), story-group
   headers, AI digest block treatment, `States` (loading skeletons,
   empty, error) matched to the new surfaces. Owns:
   `frontend/src/components/ResultCard.tsx`,
   `frontend/src/components/ResultList.tsx`,
   `frontend/src/components/States.tsx`.
4. **Wave 1C: filter sidebar flow.** `FilterPanel` + `FilterToggle` +
   `AppliedFilters` + `ProviderPrefsControl` move into a collapsible
   sidebar with active-filter chips; suggestion chip and pagination
   placement adapted to the workspace grid. Owns:
   `frontend/src/components/FilterPanel.tsx`,
   `frontend/src/components/FilterToggle.tsx`,
   `frontend/src/components/AppliedFilters.tsx`,
   `frontend/src/components/ProviderPrefsControl.tsx`.
5. **Wave 2A: diagnostics rail polish.** Frosted rail with the existing
   timeline content (request id, latencies, counts/costs, plugin
   executions, fallback, errors) plus the new cache-status badge
   (`diagnostics.cache.status`, hit/miss/error, absent when uncached);
   stays lazily loaded in its own chunk.
   Owns: `frontend/src/components/DiagnosticsDrawer.tsx`.
6. **Wave 2B: motion + a11y + fixtures.** Transition/motion classes,
   `prefers-reduced-motion` coverage, axe + keyboard + announcer tests,
   fixture refresh through `guard.ts` validation. Owns:
   `frontend/src/a11y.test.tsx`, `frontend/src/App.test.tsx`,
   `frontend/src/App.workspace.test.tsx`, fixture/test updates under
   `frontend/src/api/*.test.ts*` (no `client.ts`/`types.ts`/`guard.ts`
   logic changes).
7. **Integrate (solo).** Wire waves, full gate run, Docker
   (`deploy/local/docker-compose.yml`) visual smoke of hero → search →
   sidebar → rail, bundle-budget check, `tasks_status.md` row + session
   summary via the `record` stage. Fixes anywhere in `frontend/`; no new
   features, no `src/` edits.

## Validation Plan

- `npm --prefix frontend run lint`, `npm --prefix frontend run format:check`,
  `npm --prefix frontend test`, `npm --prefix frontend run build` green;
  `npm --prefix frontend audit --omit=dev` with no unacknowledged findings.
- Axe checks report zero critical violations on hero + results + sidebar
  + rail; keyboard-only walkthrough (search → filter → paginate → rail)
  completable without a mouse; `aria-live` announcements intact.
- `git status` shows changes only under `frontend/` plus the plan/spec;
  backend suite unaffected.
- Manual against the Docker stack: empty state shows hero; one search
  collapses to sticky header + sidebar + refined cards; disabled-AI and
  single-provider states render degraded chrome, never errors.
- Highest-risk check: frosted surfaces over real result text must hold
  contrast at 360/768/1280px — backdrop, blur, and scrolled-under content
  included, not just static comps.

## Risks / Open Questions

- Glass + blur over scrolling content is the main contrast risk; if any
  hero/sidebar/rail surface fails AA over live text, that surface goes
  solid (tokens already support it) rather than weakening the gate.
- `backdrop-filter` coverage on older browsers: acceptable degradation is
  the solid fallback wash, not a polyfill.
- Assumption (reversible): light theme kept. If a dark glass variant is
  wanted instead, say so on `go` and wave 0 re-tokens first.
- Open questions: none — all material choices resolve to the tree facts
  and constraints above.
