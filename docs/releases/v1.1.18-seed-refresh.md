# Release plan: v1.1.18 (duplicate seeds refresh, hub fan-out pin)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: Actions -> release-lightweight -> Run workflow,
`ref: v1.1.18`.

## What's in this release

- **Duplicate seeds refresh instead of no-op**: re-pasting a
  finished seed URL revives its terminal row (`done`/`failed`/
  `skipped`) back to `queued` so workers refetch it. The indexer
  already upserts by document id, so a refresh overwrites the row —
  latest crawl kept, never duplicated.
- **Hub fan-out pinned**: a link-heavy hub (homepage-shaped page
  with nav/tag-index/nofollow decoys) enqueues and fetches every
  article link. Verified live against `https://dev.to/` (230 kept
  links, 58 fetched in simulation); a lone queued URL on a
  deployment therefore means the seed never fetched (paused
  workers or a failed seed fetch), not an extraction bug.
- 3 new tests (API revive, crawler fan-out, reseed refresh without
  duplicates).

   `main`, then tag `v1.1.18` and push the tag (tags never move).
2. Actions -> release-lightweight -> Run workflow (`ref: v1.1.18`);
   watch the run.
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification (on the server)

- Paste a finished seed URL again: its row returns to `queued`
  and it refetches (row count unchanged afterwards).
- Seed `https://dev.to/`: article links fan out instead of one row.
