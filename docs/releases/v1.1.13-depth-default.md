# Release plan: v1.1.13 (default max depth 2, queued-domains freshness)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v1.1.13` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Default max depth 3 → 2**: unified across every fallback
  layer (`FrontierSettingsSchema`, in-memory `DEFAULT_SETTINGS`,
  admin `CRAWLER_DEFAULTS`, shipped `configs/default.yaml`) with
  both OpenAPI snapshots regenerated. Links deeper than 2 hops
  from a seed now skip at push time (`skipped_depth`).
- **Parent-depth inheritance verified + hardened**: probe
  confirms seed@2 → child rows at 3 → 4 → 5 in the store path
  and parent+1 in the in-memory path. The in-memory discovery
  branch no longer drops the computed child depth/priority
  (`frontier.push(link)` → same call shape as the store branch).
- **Queued-domains board shows fresh inserts**: the admin drawer
  invalidates the queued-domains queries after Enqueue seeds and
  Resume-with-seeds instead of waiting for the 60 s poll tick.
- 3 existing default-pinning tests updated to the new contract
  (settings-sync backfill ×2, shipped-yaml crawler default).
