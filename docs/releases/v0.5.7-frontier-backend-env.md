# Release plan: v0.5.7 (wire frontier backend flag into workers)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v0.5.7` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Cutover fix**: `deploy/local/docker-compose.yml` now maps
  `OPENLENS_FRONTIER_BACKEND` (`:-postgres` default) into the
  crawler and crawler-backoff containers. Without this entry the
  flag set in `release.env` never reached the workers and every
  crawl stayed on the Postgres hot path despite the setting.
- No code changes; compose-only.

## Pre-release checklist

- [ ] `git status` clean except this plan file.
- [ ] `OPENLENS_FRONTIER_BACKEND=redis` already present once in
  server `release.env` (set during v0.5.5 cutover attempt).
- [ ] No `-v` volume wipes. `redis-frontier` service already
  deployed and healthy (v0.5.5).

## Release steps

1. Tag `v0.5.7` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification (on the server)

- `docker exec <crawler> printenv OPENLENS_FRONTIER_BACKEND`
  must print `redis`.
- Crawler logs must show
  `frontier backend=redis store=RedisFrontierStore mirror=on`.
- Master CPU should fall to documents + 5 s mirror batches;
  `frontier_mirror_lag_seconds` ≤ 5.
