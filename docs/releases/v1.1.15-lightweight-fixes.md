# Release plan: v1.1.15 (lightweight crawler supervise + heartbeat)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v1.1.15` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml)
(full stack), then a manual
[.github/workflows/release-lightweight.yml](../../.github/workflows/release-lightweight.yml)
dispatch (with `admin_profile: true`) downgrades the server back to
the lightweight stack. The tag must land first: both workflows share
the `release-production` concurrency group, so the downgrade queues
behind the full deploy instead of racing it.

## What's in this release

- **Crawler supervisor loop** (`docker-compose-lightweight.yml`): store
  mode drains the frontier and exits, so a bare `crawl-worker --queue
  store` PID 1 hot-restarted forever and failed the workers health
  gate. The shell supervisor re-drains on a 30s idle cadence, forwards
  SIGTERM to the running child, and the crawler healthcheck gets a 5m
  start period for the first seed-index drain.
- **API heartbeat from store-mode drains** (`indexing/worker.py`):
  `GET /frontier/workers` reads only the ephemeral API registry, which
  only the Kafka loop fed — the lightweight crawler was invisible on
  the dashboard. Extracted the throttled reporter into
  `_make_api_reporter()` shared by both loops; store mode now beats
  with real claimed/discovery/stats. Regression test:
  `test_standalone_worker_posts_api_heartbeat`.
- **Gitleaks stays free**: `gitleaks-action` pinned to v2 — v3 fails
  the secrets job without a paid `GITLEAKS_LICENSE`.
- Bump: `pyproject.toml` 1.1.14 → 1.1.15.
