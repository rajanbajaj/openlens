# Release plan: v1.1.0 (seed depth + curated seed list)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v1.1.0` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Seed depth end to end**: `POST /frontier/seeds` accepts
  `depth` (whole number, defaults to 0), threaded through the
  Kafka topic and the store fallback instead of the hardcoded 0.
  Admin Seeds section gains a Depth input next to Priority, with
  the same inline validation. Resume is untouched (still depth 0).
- **Curated seed list**: `configs/seeds-interesting.yaml` — 35
  hubs in high/normal/low tiers with a copy-paste posting loop.
- 7 new tests (backend validation/storage/Kafka-threading,
  frontend client body + drawer submit + inline rejection).

## Pre-release checklist

- [x] `pyproject.toml` version matches the tag (`1.1.0`).
- [x] Backend gates green (1715 passed, ruff + mypy clean).
- [x] Admin gates green (140 passed, eslint/prettier/build clean).
- [ ] No env/config changes; no `-v` volume wipes.

## Release steps

1. Tag `v1.1.0` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification

- Enqueue 2 seeds with depth 2 from the admin Seeds section;
  `frontier/url-info` shows depth 2 on both.
- Post the high tier of the seed list; queue depth climbs and the
  Queue view rotates with live statuses (v1.0.0 fix in effect).
