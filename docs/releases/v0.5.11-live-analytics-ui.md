# Release plan: v0.5.11 (live analytics + UI refresh)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v0.5.11` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Live analytics socket**: `GET /api/v1/admin/analytics/live`
  pushes counts/prev-counts/throughput-series on connect and every
  `OPENLENS_ANALYTICS_LIVE_INTERVAL_S` (default 10 s, floored at 2 s).
  The panel writes frames into its query cache (no refetch storm),
  with a Live badge, Pause/Resume toggle, hidden-tab pause, and at
  most 3 reconnects. Fail-open throughout.
- **Search UI refresh**: deliberate header zones (full-width search
  row on phones), solid hero card on a wash backdrop, dead
  `ol-app-shell-collapsed` CSS removed.
- **Admin UI**: tour button moves to the `ui/Button` primitive.
- **AGENTS.md**: UI/UX subsection (theme contract, primitives-first,
  motion, a11y, responsive, human-eyes gate, honest claims).

## Pre-release checklist

- [ ] `git status` shows only the files below (plus this plan).
- [ ] No new env vars required on the server (socket default 10 s).
- [ ] No config changes; no `-v` volume wipes.

## Release steps

1. Tag `v0.5.11` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification (on the server)

- Open the admin analytics tab: the badge reads `Live • every 10s`
  and KPI/throughput values move without a manual refresh.
- v0.5.10 backfill follow-up (still open): worker log shows
  `backfill mirror→redis:` in the tens of thousands and `fw:ready`
  drains from ~62k.
