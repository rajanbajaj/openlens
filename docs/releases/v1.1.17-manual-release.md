# Release plan: v1.1.17 (seed-relative depth budget, manual release dispatch)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: Actions -> release -> Run workflow with `services: all`,
`ref: v1.1.17` (tag pushes no longer deploy).

## What's in this release

- **Seed-relative depth budget**: explicit seeds re-root the
  link-following budget at their own depth. A dev.to profile seeded
  at depth 2 with `default_max_depth: 2` now follows its article
  links (previously `skipped_depth`); an admin seed depth above the
  default (e.g. 5) is honored, never capped. Stale backlog rows
  without seed context keep absolute gating (no cap inflation).
  Kafka seed messages carry a `seed` flag so per-message drains
  re-root the budget; pre-upgrade payloads decode as non-seeds.
- **Manual release dispatch**: `release.yml` no longer triggers on
  `v*` tag pushes (matching `release-agetech` / `release-lightweight`);
  deploys run from Actions with `services` + `ref` inputs.
- `docs/wiki/Release-Process.md` updated for manual deploys.
- 8 new tests (crawler budget roots, Kafka seed flag, worker
  end-to-end, uncapped depth-5 intake).

## Release steps

1. Commit the fix, then the release commit (version bump); push
   `main`, then tag `v1.1.17` and push the tag (tags never move).
2. Actions -> release -> Run workflow (`services: all`,
   `ref: v1.1.17`); watch the `release-production` concurrency run.
3. Gates: `/healthz`, frontier status, search probe, both frontends.
