# Release plan: v1.0.0 (first major — live queue view)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v1.0.0` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

Since v0.5.13 (all green, all deployed):

- **Queue view shows the drain head**: `pending()` fetched
  `ZRANGE 0..limit` (stagnant tail) while workers claim via
  `ZPOPMAX`. Now fetches `-limit..-1` — the admin list rotates
  with real statuses. Offline regression test (true `ZRANGE`
  semantics) + live-Redis mirror.
- **Version discipline**: `pyproject.toml` now `1.0.0`; release
  rule recorded in `AGENTS.md` + `docs/wiki/Release-Process.md`
  (bump in the release commit, tags never move).
- **Wiki**: step-by-step Search and Admin Guide with prod
  screenshots (`admin-config.png` still to capture).

## Pre-release checklist

- [x] `pyproject.toml` version matches the tag.
- [x] Backend gates green (1712 passed, ruff + mypy clean).
- [ ] No env/config changes; no `-v` volume wipes.

## Release steps

1. Tag `v1.0.0` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification (on the server)

- Admin Queue list rotates with `active` badges; `queue_depth`
  keeps falling as the backlog drains.
- Kafka UI: `crawlers` / `crawlers-backoff` groups show members.
- `docker stats`: crawler + `redis-frontier` CPU down vs pre-v0.5.13.
- If CPU stays pinned with `Kafka broker unreachable` in crawler
  logs, the workers are crashlooping — separate wiring issue.
