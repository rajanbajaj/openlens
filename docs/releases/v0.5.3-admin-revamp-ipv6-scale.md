# Release plan: v0.5.3 (admin revamp, IPv6 crawler hardening, scale singletons)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v0.5.3` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Admin dashboard revamp** (`admin-frontend/`): shared `DataTable`
  (client search/sort/pagination) + `SearchInput` on every list,
  dialog-gated destructive actions, color-coded status badges,
  analytics `FeedbackCard` + keyboard-readable throughput table,
  dead-code deletion. Spec:
  [admin-dashboard-revamp](../plans/admin-dashboard-revamp.md).
  Verified: 130/130 vitest, eslint/prettier clean, `tsc + vite build`
  clean.
- **Crawler IPv6 hardening** (`src/openlens/indexing/crawler.py`):
  malformed bracketed hosts (e.g. `http://[::1`) in seeds, outlinks,
  booking/hreflang hrefs now fail terminally or drop the attribute
  instead of killing the worker (`ValueError: Invalid IPv6 URL`).
  3 new regression tests in `tests/unit/test_crawler.py`.
- **Scale workflow** (`.github/workflows/scale.yml`): `replicas=1`
  on a singleton service recreates it (ensure-one-running, nothing
  persisted); `0`/`>1` stay rejected with a message pointing at the
  release workflow and live CPU/RAM tuning. Unblocks the failed
  `postgres` / `postgres-replica` scale runs.

## Pre-release checklist

- [ ] `git status` shows only this release's files (3 commits).
- [ ] No new env vars: server-side `release.env` needs no changes.
- [ ] No `-v` volume wipes.
- [ ] Crawler/scale changes are fail-closed; admin changes are UI-only.

## Release steps

1. Tag `v0.5.3` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.
