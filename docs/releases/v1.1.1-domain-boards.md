# Release plan: v1.1.1 (domain boards stop going stale)

Target: release server (self-hosted runner `openlens-release`).
Mechanism: tag `v1.1.1` triggers
[.github/workflows/release.yml](../../.github/workflows/release.yml).

## What's in this release

- **Domain boards refresh**: Queued-by-domain / Failed-domains /
  Failed-URLs boards fetched once and froze at mount while the Queue
  summary went live. All five board queries now poll every 60 s
  (deliberately off the 2 s socket — each board is a full store
  scan), plus a **Refresh lists** button reusing the post-mutation
  path so header counts move together.
- 2 new drawer tests (on-demand refresh, 60 s interval).

## Pre-release checklist

- [x] `pyproject.toml` version matches the tag (`1.1.1`).
- [x] Admin gates green (142 passed, eslint/prettier/build clean).
- [ ] No env/config changes; no `-v` volume wipes.

## Release steps

1. Tag `v1.1.1` and push `main` + tag (tags never move).
2. Watch the `release` workflow (`concurrency: release-production`).
3. Gates: `/healthz`, frontier status, search probe, both frontends.

## Post-deploy verification

- Open the frontier tab, note the Queued-by-domain / Failed-domains
  totals, wait ~70 s: totals move without touching anything.
- Refresh lists updates counts immediately.
- Backend load unchanged (3 list scans/min while the admin is open).
